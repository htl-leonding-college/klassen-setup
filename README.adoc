Einheitliche Arbeitsumgebung für den Unterricht — Ubuntu 26.04 LTS oder macOS.
Zwei Scripts mit verschiedenen Aufgaben:

[cols="1,3",options="header"]
|===
|Script |Aufgabe

|`setup-tools.sh`
|Werkzeuge installieren. Idempotent, unbeaufsichtigt, beliebig oft wiederholbar.

|`setup-identity.sh`
|Name, E-Mail, SSH-Schlüssel, GitHub-Anmeldung. Einmalig und interaktiv.

|`versions.env`
|Die verwendeten Versionen — die eine Stelle, an der sie stehen.
|===

== Einstieg

Bewusst *kein* `curl … | bash`. Ein fremdes Script ungelesen mit erhöhten
Rechten auszuführen ist genau die Gewohnheit, die ihr euch nicht antrainieren
sollt. Der Umweg ist der Lehrinhalt.

NOTE: Eine Ausnahme gibt es, und sie wird benannt statt versteckt: SDKMAN
bietet keinen Paketweg an. `setup-tools.sh` lädt dessen Installer deshalb
herunter, legt ihn als `.cache/sdkman-install.sh` ab, nennt Pfad und Größe
und führt ihn erst dann aus. Die Datei bleibt liegen und ist nachlesbar — das
ist der Unterschied zu einer Pipe.

[source,bash]
----
# 1. Herunterladen
git clone https://github.com/htl-leonding-college/klassen-setup.git
cd klassen-setup

# 2. Lesen — was tut das Script? Welche Versionen? Wo braucht es sudo?
less setup-tools.sh
less versions.env

# 3. Ausführen
./setup-tools.sh
----

TIP: Auf einem frischen Ubuntu fehlt manchmal `git`. Dann zuerst
`sudo apt-get update && sudo apt-get install -y git` — ein einzelnes,
nachvollziehbares Kommando.

Was fehlt, ohne etwas zu installieren:

[source,bash]
----
./setup-tools.sh --check
----

Danach einmalig:

[source,bash]
----
./setup-identity.sh
----

== Idempotenz

Der erste Lauf dauert über eine Viertelstunde und führt durch ein Dutzend
Fehlerquellen: Netzausfall, `apt`-Lock, abgebrochener Download. Er *wird*
irgendwann abbrechen. Jeder Schritt prüft deshalb zuerst, ob das Werkzeug
schon da ist; ein erneuter Lauf setzt fort, statt Schaden anzurichten.

Derselbe Begriff begegnet euch bei Docker und Kubernetes wieder — dort heißt
das gewünschte Ergebnis ebenfalls: derselbe Endzustand, egal wie oft
ausgeführt.

Ein einzelner Fehlschlag beendet den Lauf *nicht*. Er wird gemerkt, die
übrigen Schritte laufen weiter, und am Ende steht unter `== Bilanz`, was offen
blieb. Der Rückgabewert ist dann ungleich 0 — andernfalls wäre „ist
durchgelaufen" keine Aussage.

`--check` endet mit 0, wenn nichts fehlt, sonst mit 1. Damit lässt sich der
Zustand eines Geräts auch maschinell prüfen.

== Voraussetzungen am Gerät

* RAM >= 8 GB (16 GB empfohlen)
* Freie Partition >= 100 GB für Ubuntu
* Virtualisierung im BIOS aktiviert
* BitLocker-Recovery-Key *vorher* gesichert
* Windows-Schnellstart deaktiviert, SATA-Modus auf AHCI

WARNING: Diese Liste vollständig abarbeiten, *bevor* die Partitionstabelle
angefasst wird. Jeder Punkt kostet jetzt Minuten und nachher einen Nachmittag;
der Recovery-Key lässt sich hinterher gar nicht mehr beschaffen.

== Versionen und Schuljahre

`versions.env` hält die verbindlichen Versionen. Je Schuljahr wird ein
git-Tag gesetzt, damit ein Stand nachträglich rekonstruierbar bleibt: Fällt
ein Fehler nur bei einzelnen Schülern auf, ist die verbindliche Version an
*einer* Stelle nachlesbar.

== Zugangsdaten

Keine im Repository. `setup-identity.sh` erzeugt den SSH-Schlüssel lokal; der
private Teil verlässt das Gerät nicht, weitergegeben wird nur `*.pub`.
